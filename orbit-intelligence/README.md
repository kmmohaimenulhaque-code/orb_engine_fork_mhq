# Orbit Intelligence — Find_Orb Integration

This directory wraps **Bill Gray’s Find_Orb** (non-interactive `fo` binary) behind a FastAPI service so the frontend can request real orbit solutions from optical observations.

## Why the solver was failing

The runtime artifacts required by the solver are **not** committed to git:

| Path | Purpose | Produced by |
|------|---------|-------------|
| `backend/bin/fo` | Compiled Find_Orb executable | `render-build.sh` |
| `backend/findorb-data/cospar.txt` | Observatory codes | `render-build.sh` |
| `backend/findorb-data/linux_p*.430*` | DE430 planetary ephemeris | `render-build.sh` (wget) |

In the repository the file `backend/bin/fo` was previously a 1-byte empty placeholder.  
`_require_find_orb()` now explicitly rejects any binary smaller than 1 KB and tells you to run the build script.

## Correct build flow (Render / local)

```bash
cd orbit-intelligence
bash render-build.sh
```

The script:

1. Clones the official Bill-Gray repositories (`lunar`, `jpl_eph`, `sat_code`, `miscell`, `find_orb`)
2. Compiles them in the correct order
3. Installs the real `fo` binary into `backend/bin/fo`
4. Copies configuration files into `backend/findorb-data/`
5. Downloads the DE430 ephemeris

After a successful build you should see:

```text
backend/bin/fo                 # several hundred KB – a few MB
backend/findorb-data/cospar.txt
backend/findorb-data/linux_p1550p2650.430t   (or similar)
```

## Running the API locally (after build)

```bash
cd backend
pip install -r requirements.txt
uvicorn main:app --reload --port 8000
```

## API contract

`POST /api/orbit/solve`

```json
{
  "object_name": "MHA-TEST",
  "observations": [
    {
      "time_utc": "2026-09-17T12:00:00Z",
      "ra_deg": 210.5,
      "dec_deg": -15.3,
      "magnitude": 18.2
    },
    ...
  ]
}
```

Minimum 3 observations. Observatory code 500 (geocentric) is used for the synthetic observations generated by the frontend.

## Design notes for Space Apps judges

- **Real NASA / community software**: Bill Gray’s Find_Orb is the same engine used by many professional minor-planet orbit computers.
- **Live path**: observations → MPC-format text → `fo` → JSON elements → 3-D path for the visualiser.
- **No fake orbits**: if Find_Orb cannot produce a solution the API returns a clear error (including the tail of Find_Orb’s own output).
- **Build-time compilation** keeps the repository small and ensures the binary matches the deployment platform.
